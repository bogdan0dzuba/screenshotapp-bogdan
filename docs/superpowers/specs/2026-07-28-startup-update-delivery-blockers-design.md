# Автозапуск, дубли и надежная доставка обновлений

## Цель

После установки должна существовать только одна физическая копия приложения, оно должно запускаться при входе пользователя в macOS, а каждый опубликованный Sparkle-релиз обязан иметь строго возрастающий `CFBundleVersion`.

## Устранение дублей

- Простое снятие регистрации через `lsregister -u` не считается исправлением: физическая `.app` может быть обнаружена повторно после перезагрузки.
- После успешного копирования и запуска установленной версии пользовательский флажок очистки означает безвозвратное удаление скачанной `.app`, а не перенос в Корзину.
- Текст флажка прямо сообщает об удалении. Удаление выполняется только после запуска установленной копии и только для исходника, отличного от установленной версии.
- Ошибка удаления показывается пользователю и не завершает уже успешно установленное приложение.
- Две подтвержденные старые резервные `.app` в Корзине удаляются один раз, после чего LaunchServices регистрирует только установленный bundle.

## Автозапуск

- Используется штатный `SMAppService.mainApp`; LaunchAgent и устаревший `SMLoginItemSetEnabled` не применяются.
- Для существующей и новой установки автозапуск включается один раз по умолчанию после подтверждения, что приложение уже запущено из `~/Applications` или `/Applications`.
- В разделе настроек рядом с автообновлением появляется переключатель `Запускать при входе в систему`.
- Переключатель отражает фактический `SMAppService.Status`, а не отдельное значение в `UserDefaults`.
- Начальный `.notFound` считается отсутствующей регистрацией и вызывает `register()`: на текущей локально подписанной установленной сборке это переводит сервис в `.enabled`.
- Одноразовый migration marker записывается только после успешного вызова регистрации; ошибка остаётся повторяемой на следующем запуске и попадает в unified log.
- Если macOS требует ручного разрешения, настройки показывают понятное сообщение и кнопку перехода к системным объектам входа.
- Ошибка регистрации не приводит к ложному включенному состоянию.

## Номер сборки Sparkle

- `CFBundleShortVersionString` остается человекочитаемой версией, например `0.5.25`.
- `CFBundleVersion` и `sparkle:version` всегда возрастают.
- Локальная и Universal-сборка берут общий кандидат из `script/version.sh`, а команда публикации перед сборкой сравнивает его с номером последнего публичного appcast.
- Публикация останавливается, если кандидат не больше публичного номера. Явный `SCREENSHOT_APP_BUILD_NUMBER` разрешен, но проходит ту же проверку.
- Проверка выполняется реальным тестовым appcast, а не поиском строк в shell-скрипте.

## Gatekeeper

- EdDSA-подпись Sparkle защищает обновление, но не заменяет доверие Gatekeeper к первой установке.
- Полностью убрать правый клик `Открыть` можно только подписью `Developer ID Application` и нотарификацией Apple.
- До появления сертификата и notary-профиля релизный процесс обязан честно помечать клиентскую установку как требующую ручного открытия.
- Необходимые внешние значения: действующий сертификат `Developer ID Application` в Keychain и сохраненный профиль `notarytool`.

## Проверка

- RED/GREEN-тест политики очистки запрещает оставлять исходную `.app` после согласия пользователя.
- RED/GREEN-тест автозапуска проверяет регистрацию, отключение, `requiresApproval` и ошибку без ложного состояния.
- RED/GREEN-тест номера релиза проверяет увеличение относительно appcast и отказ при равном или меньшем числе.
- Полная SwiftPM-сборка и существующие проверки проходят.
- Локальная установленная версия запускается, имеет один физический bundle и статус login item `enabled` либо подтвержденный `requiresApproval`.
- Клиентский ZIP, appcast и checksum проверяются отдельно; Gatekeeper не объявляется исправленным без реального Developer ID и нотарификации.
